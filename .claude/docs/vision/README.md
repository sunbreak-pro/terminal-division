# Vision

実装計画書として具体化しきれていない構想・ビジョン・抽象的な設計原則を置くディレクトリ。

## 役割

- **実装プランとの違い**: 実装プラン（`.claude/YYYY-MM-DD-<slug>.md`）は具体的な手順・検証基準を持つ（完了後 `archive/` 行き）。vision/ は「なぜそれを作るのか」「どう進化させたいか」「設計判断の背景」など抽象度の高い議論・要件・原則を長期保管
- **CLAUDE.md との違い**: CLAUDE.md は現状の SSOT（実装済みの規約・アーキテクチャ）。vision/ は未実装の構想や、CLAUDE.md に入れるには詳細すぎる背景情報
- **ADR を作らない理由**: ADR は「時点の判断」を固定してしまい、古い情報を参照しがち。vision/ は「現在から未来に向けた設計原則」として継続更新できる

## 推奨ファイル構成

| ファイル               | 内容                                                         |
| ---------------------- | ------------------------------------------------------------ |
| `core.md`              | Core Identity / Target User / Value Propositions / Non-Goals |
| `coding-principles.md` | 設計原則の集約（旧 ADR の役割、過去判断の記録・背景）        |
| `<topic>.md`           | 個別トピックの構想・要件（必要に応じて）                     |

## ライフサイクル

- 構想段階 → vision/ に記述
- 実装フェーズに入る → 実装プランを `.claude/YYYY-MM-DD-<slug>.md` に作成、vision/ ファイルから相互リンク
- 完全実装済み → 実装規約は CLAUDE.md 該当章に統合、vision/ ファイルには「なぜ」と「将来再評価トリガー」を残す
